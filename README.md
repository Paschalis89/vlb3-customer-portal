# VLB3 Customer Portal - STEP 8

Customer-facing portal for the VLB3 platform.

STEP 8 adds the customer activity history. The `/history` page now contains a responsive timeline with remote pump operations, frequency changes, resolved alarms and device online/offline events. Technical events such as JWT refreshes, command leases, API retries, Docker restarts and raw Modbus diagnostics are intentionally excluded.

## Customer history model

The customer timeline exposes only meaningful operational events:

```text
PUMP_STARTED
PUMP_STOPPED
FREQUENCY_CHANGED
ALERT_RESOLVED
DEVICE_OFFLINE
DEVICE_ONLINE
```

It deliberately does not expose internal events such as:

```text
JWT renewed
command lease
worker retry
API retry
Docker restart
raw Modbus errors
raw registers
provisioning events
agent internals
```

## Dynamic demo history

Successful demo commands are added to the history automatically.

Example:

```text
Campo Sud
  -> START
  -> QUEUED
  -> DELIVERED
  -> SUCCEEDED

/history
  -> Pompa avviata
  -> Campo Sud · Pompa principale
  -> Mario Rossi
```

The dynamically generated demo events are persisted in browser local storage so they remain visible after a browser refresh.

## Important command rule

The portal never declares a command successful only because the server accepted it.

```text
START / STOP / SET FREQUENCY
        |
        v
QUEUED
        |
        v
DELIVERED
        |
        v
ACK / execution result
        |
   +----+----+
   |         |
   v         v
SUCCEEDED   FAILED / EXPIRED
```

Only `SUCCEEDED` generates a successful demo history event and updates the local device state.

## Run with Docker

Create the environment file:

```bash
cp .env.example .env
```

Build without cache:

```bash
docker compose build --no-cache
```

Start:

```bash
docker compose up -d
```

Check:

```bash
docker compose ps
```

Logs:

```bash
docker logs -f vlb3-customer-portal
```

Health check:

```bash
curl http://localhost:8080/healthz
```
